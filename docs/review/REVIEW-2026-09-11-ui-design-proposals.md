> **证据来源**：仓库内 5 张归档截图（`docs/screenshots/*.png`，2026-09-01 版，**早于当前 HEAD 约 10 天**）

> 我无法在真实浏览器渲染，凡涉及"实际观感"的判断都标注了依据；P0 项建议逐条在浏览器里核对。
> 已在此前两轮修掉的项（对比度、深色载体、进度框关闭语义、死按钮、手机端入口等）不再重复列入。

## 0. 全局层面的 6 个根因（后面所有分区问题几乎都由它们派生）

| # | 根因 | 实测证据 |
|---|---|---|
| G1 | **间距/字号/圆角没有收敛成 token** | `text-xs` 186 处 / `text-sm` 271 处；`rounded-md` 159 / `rounded-lg` 50 / `rounded-xl` 1；`p-4` 48 / `p-3` 11；同类主按钮 7 处 14px vs 7 处 16px |
| G2 | **三栏固定宽 + 中间自适应** | 侧栏档位 <900:200/240、<1100:240/280、<1280:280/320、≥1280:320/384（`data-and-ui.js` 档位表）→ 1440 屏中间仅约 700px，双列各约 350px |
| G3 | **信息密度偏低** | 列表行 = 文本 + 状态徽章 + 上下文提示三行；`p-3/p-4` 撑高 |
| G4 | **层级过平** | `text-lg` 仅 27 处，正文大量 `text-sm/xs`；卡片/分区/列表主要靠字重区分 |
| G5 | **模态宽度无阶梯** | 内层 `max-w-md` ×8、`max-w-2xl` ×3、`max-w-3xl` ×4、`max-w-4xl`、`max-w-5xl`、`max-w-6xl` 混用 |
| G6 | **状态表现不统一** | 徽章、进度、空态、表格行在各面板各写一套工具类（质量报告标签页徽章刚与面板徽章统一） |

**建议**：在 `config/tailwind.config.js` 里定义语义化组件类（`.btn-primary/.btn-ghost/.field/.panel/.badge/.empty-state/.focus-ring`），
并固定 3 档字号（12/14/16 用于正文，18 用于区块标题）、3 档圆角（控件 md、卡片 lg、徽章 full）、3 档图标（16/20/24）。
这一步做完，G1/G4/G6 会一起收敛。

## 1. 顶部工具栏

**现状**（截图 01/03/05）：两行。第一行＝语言对 + 交换 + 引擎类别/引擎/模型（"AI / DeepSeek" chips）+ 主操作；
第二行＝搜索框 + 查找替换 + 更多。

**问题**
- 引擎/模型选择与右栏"翻译引擎设置"**重复**（同一设置的第二个入口）。
- 窄屏靠 `hidden sm:flex` 隐藏控件 —— 这正是手机端"全部翻译"一度不可达的原因（已补菜单入口，但机制仍在）。
- 两行占约 96px，直接压缩列表可视区。

**建议**
1. 工具栏降为**一行**：语言对 + 搜索 + 主操作（翻译选中/全部/取消）；引擎与模型信息移到右栏或状态栏，作为"当前引擎"只读显示 + 点击跳设置。
2. 宽度不足时改为**溢出到"更多"菜单**（而不是 `hidden`），保证任何视口下功能都在。
3. 加 `sticky top-0` + 滚动时投影，滚动长列表时不丢操作。

## 2. 左侧文件面板

**现状**：拖拽上传区（约 150px 高）→ 文件搜索 → 文件列表（文件名 + 67% + 1 KB）→ 底部"项目状态 就绪"。

**问题**
- 已有文件时，拖拽区仍占首要位置，信息效率低（截图 01 中，三行文件信息被一块大虚线框压到下方）。
- 文件行把"进度/大小"用同一种浅灰小字呈现，**主次不清**（百分比是状态、大小是元数据，应分开）。
- 没有排序、筛选、批量选择（多文件项目里定位困难）。
- "项目状态 就绪"独立占一行，与顶栏的项目名/保存状态分散在两处。

**建议**
1. 有文件后把拖拽区收成一行 `＋ 添加文件`（大拖拽区只在**空态**出现）。
2. 文件行改两行式：文件名（主）+ 右侧进度环/百分比；大小与格式作为第二行元数据；未翻译 >0 时百分比用主色。
3. 支持按名称/进度/大小排序，并加"仅显示未完成"筛选。
4. 把"项目状态"与项目名合并到顶栏右侧（一处即可）。

## 3. 中间原文/译文双列（核心工作区）

**现状**（截图 01/03）：列头（标题 + `6 项` / `4/6 项`）+ 双列滚动区；每行＝源文文本 + （中缝）状态徽章 + 译文 textarea + 上下文提示。

**问题**
- 1440 屏下每列约 350px，长英文句频繁折行（截图里 "The API endpoint requires authentication." 已折两行）。
- **行高不齐**：源文长短不一时行高由较长者决定，截图第 4/5 行明显比前几行高，视觉节奏被打断。
- **状态徽章夹在双列中缝**，"已翻译/待翻译"看起来像分隔符而不是状态。
- 译文框缺少"正在编辑"的视觉状态（focus 只靠浏览器默认描边，而该描边在多处被 `focus:outline-none` 关掉过）。
- 上下文提示（"应用启动欢迎语"）字号最小（`text-xs`）+ 浅灰，读起来费劲（对比度已在上一轮修到 7.56，但字号仍偏小）。

**建议**
1. **视图切换**：双列 / 仅原文 / 仅译文；窄屏默认单列（当前 `hidden md:flex` 让手机端只有一列，但缺显式切换）。
2. 行高用 `items-start` + 统一 `min-h-[72px]`，让短行也有稳定基线；长文本保持自适应而不是内部滚动。
3. 状态改为**行首 3–4px 色条 + 悬浮徽章**（或行首圆点 + tooltip），把中缝还给"原文↔译文"的对比轴。
4. 译文框 focus 时加左侧主色边 + 极浅主色底，明确"正在编辑这一条"。
5. 上下文提示折叠进可聚焦的 ⓘ tooltip；空态提示里写明已有的键盘效率点（`Tab/Shift+Tab` 在译文框间跳转、`Ctrl+Enter` 等）。

## 4. 右侧设置面板

**现状**（截图 01/03/05）：三个标签（翻译设置/术语库/质量报告）→ 引擎类别/引擎/模型/温度 → 完整设置、翻译记忆库、自定义引擎 → 底部"导出翻译"主按钮。

**问题**
- 标签文字在窄栏内**折行**（"翻译设/置"、"质量报/告"；已作为 U3 记录）。
- 一屏内混放"设置型"控件与"打开型"入口（术语库/质量报告/记忆库本质是打开模态框）。
- 温度只有 `0.3` 与两端刻度标签（精确(0)/创意(2)），**没有"当前值"的语义说明**。
- 右栏承担了与工具栏重复的引擎选择职责。

**建议**
1. 标签 `whitespace-nowrap`，或改成"图标 + 短标签"（引擎 / 术语 / 质量）。
2. 温度行改为：`标签 + 当前值徽章 + 滑块 + 三个预设（精确/平衡/创意）`，并说明"越低越保守"。
3. 把"打开型"入口独立成一个"工具"分组（与设置项之间有分隔线与小标题），视觉上区分"改设置"与"开窗口"。
4. 右栏成为**引擎设置的唯一入口**（工具栏只显示当前引擎，点击滚到/打开此处）。

## 5. 模态框族

| 模态 | 现状 | 建议 |
|---|---|---|
| **设置**（`max-w-4xl`） | 左导航 8 项；数据管理页内容稀疏、数字输入框通栏（截图 05 的大片留白）；无设置搜索 | 数字输入定宽（`w-24/w-32`）+ 单位后缀；内容按"卡片分组 + 一句说明"排版；导航 8 项→3 组（外观/翻译/数据）；加设置搜索（≥8 项值得） |
| **质量报告**（`max-w-5xl`） | 4 张统计卡 + 雷达 + 柱状图；图表被可视高度截断（U4） | 图表容器随视口高度（`h-[clamp(180px,30vh,280px)]`）；卡片补"目标/上次对比"；"重新检查 + 上次检查时间"移到标题栏工具栏；问题表移到图表下方并可折叠 |
| **术语库**（`max-w-2xl`） | 表格 4 列；操作列混用"编辑"文字链接 + 垃圾桶图标；无排序、无批量选择（截图 03） | 操作列统一为图标按钮组（编辑/删除）+ `aria-label`；表头可排序；行加 hover/选中态；加批量删除与批量改词性；空态给"导入 CSV"主操作 |
| **导出**（`max-w-md`） | 格式单选 + 选项 | 每个格式旁加一句"能否原格式回写 / 会丢什么"（如 YAML 仅对带 path 的条目有效），避免选错后才发现 |
| **进度**（`max-w-md`） | 进度条 + 日志 + 暂停/继续/重试/取消（已完成关闭/取消语义修复） | 补 ETA 与已用时间；日志按文件分组；失败项给"仅重试失败项"直达 |
| **Prompt 模板**（设置内） | 4 个 9 行 textarea 平铺 | 折叠分组 + "恢复默认 / 与默认对比" + 变量占位说明 |
| **查找替换 / 项目 / 帮助 / 关于** | 宽度 `md/2xl/3xl` 混用 | 按三档收敛；帮助与关于合并为"帮助中心"两个标签 |

## 6. 移动端（<640px）

**现状**：顶栏 + 底部四格（文件/翻译/全选/设置）+ "更多"菜单；侧栏改抽屉（已加 `inert`）。

**问题**
- 底部"翻译"只等价于"翻译选中"（全部翻译本轮已补进"更多"菜单）。
- 底部栏与"更多"菜单**职责重叠**（全选/设置两处都有入口）。
- 双列在手机上退化为单列，缺"原文参考"的按需查看方式。

**建议**
1. 底栏简化为 3 格：文件 / 翻译 / 更多（全选、设置并入更多）。
2. 编辑译文时把底栏临时替换为"保存 / 下一条"操作条，减少来回滚动。
3. 移动端单列 + 可选"原文折叠条"（当前条目上方一行可展开的原文）。

## 7. 低成本一致性清单（可与上面并行）

- **焦点样式**抽成 `.focus-ring`（现在既有 `focus:ring-*` 也有 `focus-visible:ring-*`，还有 5 处仅 `focus:outline-none` 刚补环）。
- **图标尺寸**收敛到 16/20/24（实测混用 `text-xs`…`text-4xl` 与 `w-4/w-5/w-6`）。
- **徽章**统一 `.badge`（尺寸 + 语义色 + 可选图标），替换手写 `rounded-full px-2.5 py-1 …`。
- **空态**统一 `.empty-state`（图标 + 标题 + 一句说明 + 一个主操作）。
- **表格**统一（表头 `text-xs` 字重、行 hover、选中态、操作列右对齐）。
- **深浅色语义类**：`.dark-mode` 已迁到 `<html>`，建议顺带把散落的 `dark:` 手写类收敛为 `.surface / .surface-muted / .text-muted`，从机制上减少"某处漏写 dark:"（现在靠审计发现）。

## 8. 优先级建议

**P0（体验影响大、成本低，建议一批做完）**
1. 工具栏降为一行 + 窄屏改溢出菜单（不再 `hidden`）。
2. 右栏标签不再折行；温度行补当前值与预设。
3. 列表密度开关（紧凑/舒适，持久化到设置）。
4. 设置页数字输入定宽 + 卡片分组（顺带解决内容稀疏）。
5. 模态宽度三档收敛；统一焦点环与徽章类。

**P1**
6. 质量报告：图表高度 + 卡片信息 + 标题栏工具栏。
7. 术语库：排序 / 批量 / 操作列图标化 / 空态主操作。
8. 空态统一并补主操作；文件面板"有文件后收起拖拽区"。
9. 移动端底栏 3 格 + 编辑态操作条。

**P2**
10. 设计 token 与组件类收敛（G1/G4/G6 的根治）。
11. 双列视图切换（双列/仅原文/仅译文）+ 行首状态色条。
12. 图表与表格的进阶交互（下钻、导出选中、列宽拖拽）。

## 9. 已实施（2026-09-11，本轮落地）

以下来自 §1–§7 的条目已完成并通过验证（合约测试见 `tests/ui-integration-contract.test.mjs` 的「布局优化」组）：

| 项 | 做法 | 验证 |
|---|---|---|
| **右栏标签断行（U3）** | `.sidebar-tab span` 加 `text-wrap: balance`；新增 `.sidebar-narrow` 模式（纯图标），由 `applySidebarWidthsForLayout()` 按**实测侧栏宽度**（<300px）切换；三个标签补 `aria-label`，图标模式下仍有可访问名 | jsdom 运行时：240px 档位（实际下限 280px）→ `sidebar-narrow: true`；384px → `false`；3/3 标签 aria-label 存在 |
| **列表行高不齐** | 语境与资源 ID 由两个段落合并为一行（`语境 · ID: x`，`truncate` + `title`），桌面双列与移动合并列表两条渲染路径都改 | 运行时：每行段落数由「最多 3」降为固定 2（`[2,2,2,2,2,2]`），`rows with >2 paragraphs = 0` |
| **设置页数字输入通栏** | `#autosaveIntervalSeconds` 由 `w-full` 改 `w-28`（标签已写「（秒）」） | 合约测试断言 + 重建 CSS 后 `.w-28` 已生成 |
| **设置页内容稀疏** | 数据管理三个分组（自动保存 / 文件存储 / 导出数据）改为卡片（`rounded-lg border p-4`），去掉 `border-t` 分隔线 | 合约测试 + 截图对照 |
| **模态宽度无阶梯** | 列表类收敛到 `3xl`（项目列表、术语库），报告类收到 `5xl`（AI 会话查看器）；最终分布 md×7 / 2xl×1 / 3xl×7 / 4xl×1 / 5xl×2 | 合约测试断言四个代表模态的宽度 |
| **JS 生成标记的对比度** | 行内 ID 行、移动端空状态提示等 `text-gray-400` 一并提到 `gray-500/600`（与上一轮 HTML 扫描同源） | 合约测试断言 render.js 不再出现旧类组合 |

**顺带纠正了我自己的一个判断**：我原计划给行加 `min-height`，核对后发现 `sync-heights.js` 已经强制
`baseMinHeight = 90px`（平板 80 / 横屏矮窗 50）并写显式高度，CSS 再设下限是**冗余且无效**的，因此没有加。

**仍未实施**（§8 的 P1/P2 剩余项）：工具栏降为一行并改溢出菜单；术语库表格排序/批量操作；
质量报告图表高度与卡片信息；移动端底栏 3 格；设计 token 与组件类收敛（`.btn/.panel/.badge/.empty-state`）；
双列视图切换（双列/仅原文/仅译文）与行首状态色条。
