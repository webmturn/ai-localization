## 已完成

| 问题 | 修复后的行为 |
| --- | --- |
| 已知格式错误退回文本并误报成功 | JSON、YAML、CSV、XML 等解析失败返回明确诊断，不生成可翻译的错误条目 |
| 失败导入覆盖已有文件 | 解析成功后才保存原始内容；只有成功文件进入合并流程，同名文件失败时保留原文件与译文 |

| YAML 多文档被逐行当作文本 | 使用完整解析库处理多文档，各文档保留独立身份；导出保持文档分隔；锚点循环明确报错 |
| 旧编码被第一个非严格候选误判 | BOM/编码声明优先；候选严格解码并按文字特征评分；自动尝试旧编码时提示核对；新增手动编码选择 |
| 导出编码声明与实际下载不一致 | PO、Qt TS 导出的声明统一匹配 UTF-8 下载内容 |
| 格式入口与开关不一致 | 文件选择器列出 YAML/YML、CSV/TSV、POT；YAML 和 CSV 有独立开关，不再受文本兜底开关误拦截 |
| 选择/拖放固定 10MB | 两个入口都使用文件处理设置中的大小限制 |
| Android 禁译数组与 RESX 非文本资源进入翻译 | 禁译字符串、数组、复数全部过滤；RESX 数值和二进制资源过滤；已识别格式的空结果不会被通用 XML 再次提取 |
| PO/Qt 复数无法独立校对 | 已存在的复数形态分别成为可编辑条目；原格式导出按形态定位，修改一项不覆盖其它形态 |
| 原始状态、分段与辅助信息不足 | PO fuzzy、Qt unfinished、XLIFF 待处理状态保留；废弃 Qt 消息过滤；XLIFF segment 标识展示；注释、引用和原始状态可展开查看 |
| 重复 key 误报 | YAML 文档、XLIFF 分段和 PO/Qt 复数使用完整资源身份，正常分段/上下文不会被误报 |
| 通用 XML 漏掉短文本、CDATA 和属性 | 单字符、CDATA 及常见可翻译属性提取；导出按节点路径定位，支持同文异译 |
| iOS 特殊转义与损坏引号 | 大写 Unicode 转义正确解码；未闭合字符串明确失败 |
| XML 内联标签校对杂乱 | 原文中的内联标签显示为紧凑标记，实体显示为可读字符；完整 XML 仍保留在模型中，标签悬停可查看完整内容 |
| 文件进度只按译文是否存在计算 | 明确处于待处理状态的条目不计入已翻译百分比，与工作区统计一致 |

## 旧项目兼容

新导入或源文件重新解析后使用新的复数模型。旧项目保存源文件时，能确定形态的 PO/Qt 人工译文会保留；旧 Qt 复数包含无法区分形态的额外换行时，中止此次保存并保留原项目内容，显示明确原因。

导出继续兼容旧项目没有复数下标、没有精确节点路径的条目。

## 范围

本轮修复现有格式的已复现问题，没有宣称覆盖各格式标准的所有可选结构。旧编码自动识别仍可能存在歧义，手动编码选择是确定编码的方式。通用 XML 保留文本片段与原节点的对应关系，未增加任意 XML 的专用语义编辑器。

Excel、Word、PDF 等新格式专用导入，以及 CSV 的可视化自定义列映射，不在本轮实现范围内。
