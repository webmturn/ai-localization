# 原格式导出补充修复

日期：2026-10-08。继续检查多格式解析与显示后的导出链路，基于 v1.4.0 实施。

## 修复内容

| 已确认的问题 | 修复后的行为 |
| --- | --- |
| CSV、TSV、YAML、YML 可导入，但原格式导出没有对应处理 | 从「原格式（按导入文件）」逐文件生成对应扩展名的结果 |
| 仅重建 YAML 翻译条目会遗漏非文本值及未选中内容 | 原格式导出加载完整原文，按文档和真实路径回写；保留数字、布尔值、空值、日期、二进制值、数组位置及未选中资源 |
| YAML 别名共享对象，某项译文可能连带覆盖其他路径 | 按路径复制对象，允许别名对应的不同资源分别校对和回写 |
| JSON 根节点为字符串时，空路径被当作无效路径 | 根字符串正确写入译文；兼容旧项目仅有 `$` 路径的条目 |
| 单文件错误中断整个批量导出 | 捕获文件级错误，继续处理后续文件，提示成功/失败数量、失败文件及原因 |
| 原格式导出错误只提示失败数，无法定位文件 | 损坏 YAML 提示中文原因和行列位置；源文/路径变化提示重新导入；不支持的格式明确说明 |
| 原文件采用 CR 行尾时，CSV 行位置识别错误 | CSV 行解析支持 LF、CRLF、CR；原格式导出使用源文件的行尾类型 |

CSV / TSV 按原始逻辑行号和列号定位，保留额外列、空行、表头、未选中译文以及引号、分隔符、字段内换行、前后空格。重复 key 不会影响回写定位。资源内容以文本原样保留，公式样式字符串不会被自动附加单引号。

CSV / TSV 或 YAML 的源内容与条目位置不一致时，明确失败，避免写入另一行或路径。YAML 旧项目只有路径字符串时从原文恢复真实路径；带点字面键与嵌套路径有歧义时拒绝猜测。

## 限制

YAML / YML 原格式导出保留数据内容与结构，但通过 js-yaml 重新生成文本，不保留原注释、缩进风格、锚点名称或引用写法。CSV / TSV 的字段引号写法可能规范化。帮助中心已说明 YAML 的排版限制。

缺少原始内容时可生成通用结构并显示提示，无法恢复原文件中未保存的额外数据。本记录完成时，TXT 和未知扩展名的原格式导出尚未支持；后续文本解析与导出已在 [2026-10-09 补充修复](text-format-fixes-2026-10-09.md) 中实现。
