# 文本解析与原格式导出修复

日期：2026-10-09。继续完成多格式审查中 TXT 与文本兜底导入的缺口，版本号保持 v1.4.0。

## 已完成

| 已复现的问题 | 修复后的行为 |
| --- | --- |
| 正文的冒号、逗号、URL 中的等号被当成分隔符，导致原文截断 | 默认自动模式只识别简单键名或引号键名后的 `key=value`，其余正文保留整行 |
| 普通文本行尾反斜杠会吞掉下一行 | 普通文本保留反斜杠；新键值条目只有行尾奇数个反斜杠才续行，缺少下一行时明确失败 |
| 无法区分正文与键值资源的导入需求 | 文件处理设置新增自动、逐行文本、键值文本三种模式，并保存到设置及文件元数据 |
| 空键值资源被用 key 本身充当原文 | 新导入跳过空值，原行仍保留在源内容中 |
| 同一个 key 在不同 section 被当成重复资源，编辑源文件后译文可能串位置 | section 进入资源身份和显示上下文；源文件重新排序时保留各 section 对应的译文 |
| 引号键中的分隔符、值中的等号/冒号导致拆分错误 | 引号键内的符号保留，键值模式使用键后的第一个分隔符 |
| TXT 与实际按文本导入的文件不能按原格式导出 | 按原行位置回写，保留原扩展名或无扩展名文件名 |
| 选中部分文本导出无法保留其他行及格式 | 原格式导出保留未选中内容、注释、分隔符、引号、缩进、BOM、各行原行尾和末行无换行的状态 |
| 切换全局模式后，源文件编辑器重新解析会改变已导入文件的含义 | 编辑器沿用文件保存的模式，并保留人工译文；旧项目继续使用原解析规则 |

译文回写会重新解析缓存原文，核对原文、行位置、资源键及 section。原内容不匹配或条目范围重叠时明确失败，避免写到另一条资源。文本缺少原始内容时提示重新导入或使用 JSON/CSV 导出。

## 模式与范围

- 自动模式识别明确的 `key=value`，跳过空行、注释及 section 标记；正文里的冒号、逗号不会触发键值拆分。
- 逐行模式保留全部非空行，包括 `#`、`;` 等开头的文字、`[标题]`、Tab 和等号，适合正文。
- 键值模式支持等号、冒号、Tab、逗号及续行，适合简单键值文本。引号包裹的值去掉外层引号，反斜杠转义按字面保留；没有宣称实现 Java properties、INI 等格式的全部语义。
- 已保存的旧项目不会自动改变解析含义；源文件编辑器和导出兼容旧模式。新设置在重新导入时生效。
- 选中的键值续行会合并为一条物理行；未选中的续行保留。键值译文中的实际换行会阻止该文件导出，提示改为单行；逐行文本的实际换行可按源文件行尾写出。
- 原格式导出保留 UTF-8 文本内容和行尾，不恢复源文件的旧字节编码。
